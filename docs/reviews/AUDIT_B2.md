## Highest severity first

### HIGH
- R2-1 CONFIRMED. Carry-forward is never triggered for debts logged after the last rollover run of a month. data/service MonthlyRolloverWorker.kt (executeRollover runs only when day >= 25, target = next month). On the 1st the worker targets the month after next, and the next-month tab already exists, so the "tab created, enqueue carry" path in TransactionRepositoryImpl does not fire either. A debt logged on the last evening (or delivered late after midnight) stays Pending in the old tab and is missing from the new tab. Fix: also run carry for (current month, previous month as source) on days 1 to 3, and after any delivery whose tab month is before the current month.
- R2-2 CONFIRMED. Fake data in the shipped UI: presentation/screens/drawer/SubscriptionsScreen.kt:~373 shows "Next due 20 Dec 2026" for every subscription row. Fix: compute from SubscriptionScheduleUseCase.
- R2-3 CONFIRMED. SubscriptionsScreen.kt:~160-164 builds "next due" from the ANCHOR date (day and month of anchorEpochDay), not the next due date, and SubscriptionsViewModel.kt:74 picks active.firstOrNull() instead of the soonest. Fix: next due = first dueDate >= today.
- R2-4 CONFIRMED. Contact-named SMS senders are not treated as personal. core/utils/RegexPatterns.kt isPersonalSender only checks digits or a leading plus. A friend saved as a name whose text contains "received" or "paid to" plus a rupee amount passes hasFinancialKeywords and becomes a capture (privacy rule: never read personal messages). Fix: allow SMS only from sender ids that look like bank headers (letters, dashes, short codes) and drop names with spaces or lower case words.
- R2-5 CONFIRMED. Notification content is not private on the lock screen: no setVisibility anywhere (grep). Capture heads-up, subscription reminders and sync alerts show payee and amount even when app lock is on. Fix: VISIBILITY_PRIVATE with a public version.
- R2-6 CONFIRMED. Month burn widget shows the burn amount on the home screen regardless of app lock (service/MonthBurnWidgetProvider.kt has no lock check). Decide and document, or add a "hide amount" option tied to app lock.

### MEDIUM
- R2-7 CONFIRMED. Recents preview leaks with app lock on: FLAG_SECURE only when hide_recents_preview is on, default false (PreferencesRepository.kt:190), and the lock engages 60 s after backgrounding. Fix: when app lock is on, apply FLAG_SECURE always, or lock immediately on stop.
- R2-8 CONFIRMED. Income card counts "Refund / Return" as income (DashboardViewModel.kt:~455) while the same refund also lowers living burn (LivingBurn.refundTotal): the refund is counted twice in the cash picture. Fix: remove refunds from the income card.
- R2-9 CONFIRMED. After refunds, per-category amounts no longer sum to the total: LivingBurn.total is net and clamped, byCategory is gross (documented in 218124c). Dashboard percentages are sum/currentBurn capped at 1, so rows can show more than 100 percent in total; Insights slices use the gross total for percent while the donut centre shows the net total (InsightsCalculator.kt slices vs total). Budgets use gross categories. Fix: show a "refunds" row, or compute percent against the gross total.
- R2-10 CONFIRMED. A refund of a purchase in an excluded category (Savings, Transfer) still lowers living burn (inflows carry no category).
- R2-11 CONFIRMED. Edit during an in-flight first delivery is lost: TransactionRepositoryImpl.updateTransaction (f8a82a2) skips OP_UPDATE while an OP_INSERT with planJson == null is queued, but updateTransaction takes no syncMutex. If sync already read the row and has not stored the plan yet, the edit never reaches the sheet, and the next reconcile overwrites the local edit with the old sheet value. Fix: take the sync lock in updateTransaction, or queue the update when the insert is IN_PROGRESS.
- R2-12 CONFIRMED. Hand edits to tabs older than the previous month never reconcile (5caa4d1: two-month read), and a reconcile needs a changed Drive modified time or delivered queue work plus the 10 minute gate. Current-month hand edits do reconcile. Document, or add a manual "full refresh".
- R2-13 SUSPECTED. SubscriptionReminderWorker.schedule uses CANCEL_AND_REENQUEUE on every process start (FinanceApplication). Opening the app inside the 15 minute flex window before the reminder time cancels the pending run; that evening's reminder is skipped.
- R2-14 CONFIRMED. Config upsert appends new rows one request group at a time: data/repository/ConfigRepositoryImpl.kt:~106-120 calls appendTableScoped per row (a read, a metadata fetch and a write each). A first mirror of N rows costs about 3N to 4N requests and feeds the 429 cooldown. Fix: one values.append for all new rows.
- R2-15 CONFIRMED. GoogleSheetsClient.appendTableScoped ignores the result of ensureGridCapacityBeforeAppend (~line 342). If the grid expansion fails, the write fails with HTTP 400, which is classified permanent. Fix: return the capacity error and treat 400 "exceeds grid limits" as retry after expansion.
- R2-16 CONFIRMED. A half-provisioned month tab is never repaired: GoogleSheetsClient.ensureMonthTabExists (~621) returns false as soon as the tab title exists, but provisionMonthTab creates the tab (addSheet) and formats it in a second request. A failure between them leaves a bare tab forever. Fix: validate the layout (WorkbookResolver.checkTabHasValidLayout) when the tab exists, repair if invalid.
- R2-17 CONFIRMED. Year boundary: carry-forward only looks for the preceding tab inside the same workbook (AccountingSyncExecutor.executeCarryForward findPrecedingTab). January of a new yearly workbook never receives December debts. Fix: explicit year-close carry or read the previous workbook.
- R2-18 CONFIRMED. RegexPatterns: AMOUNT_REGEX takes the FIRST rupee amount, so an SMS that mentions a balance or limit before the debit amount records the balance. MERCHANT_REGEX alternation has no word boundary before "to" and "at" (matches inside words such as auto, photo). VPA_REGEX takes the first address-like token, which can be a customer-care email. Fix: prefer the amount next to the debit verb; add \b; require a UPI handle without a dot after the at sign.
- R2-19 CONFIRMED. TripSummaryUseCase: "returned" sums owedToMe of SETTLED rows, but settled rows have owed 0, so it is always 0; totalPaid sums totalAmount of all non-void rows including carried-forward copies, double counting across month boundaries (domain/usecase/TripSummaryUseCase.kt ~32-60).
- R2-20 CONFIRMED. SubscriptionsViewModel monthly total counts a weekly subscription at 4.33 and a yearly one at 1/12 but shows it as "spend"; fine as an estimate, but a null amount counts as 0 silently.
- R2-21 CONFIRMED. Void display: "Voided" is a hard-coded literal in StatusChip.kt and the three row composables (42e44b5) although the branch moved text to strings.xml (status_voided exists). DashboardViewModel.kt:~381 (queued items) and TransactionsViewModel.kt:~398 (search) still use the raw merchant, so the "[Void] " prefix shows in the offline queue list and any search for "void" or "oid" matches every voided row. Fix: strip in both places; search on the stripped text.
- R2-22 SUSPECTED. SyncTransactionsWorker gives up after 3 attempts inside a 429 cooldown (each retry returns the cooldown error immediately), so only the next save or the 15 minute periodic job resumes the queue. Not a starvation, but the first three retries are wasted.
- R2-23 CONFIRMED. The sync lock is held for the whole network run; void and undo (A-1) wait for it, so an Undo tapped inside the 8 second pill can finish after the pill is gone.

## Checked and found correct

Sheet formula uses columns I, F, P, S that match the 31-column layout (Table 2 type in P, amount in S). Refund type strings "Refund / Return" and "Refund" match inflow_type_return in strings.xml.
- Atomic append: one batchUpdate writes cells and the id, so an interrupted append cannot leave an orphan; retry finds the row by id (findRowByUuid indexes correctly, empty rows keep their position).
- SheetProvisioner: idempotent (unmerge then merge, validation cleared, rule formulas de-duplicated), no deletes, no value writes below row 3; WorkbookResolver backs up before a forced repair and never overwrites cloud config with local defaults.
- Strings: every R.string reference exists; 89 formatted strings checked against call sites (argument counts and order match, including onboarding_error_generic and insights_*); widget templates are formatted later with String.format. UiText: no null path found; no caller reads resId directly.
- removePerson and removeTripTag: refuse with an open balance or active trip, archive instead of delete, rebuild skips archived names, a new transaction restores them, flag syncs via the archived field.
- SheetsReadGate: cooldown is bounded (15 min max), force limited to once a minute, a hand edit of the current or previous month tab is picked up through the Drive modified time.
- App lock paths: NavHost is composed only after unlock (all routes gated), overlay hides names and balances when locked, app_lock_enabled and hide_recents_preview are local-only prefs and not mirrored.
